## 二、做对了什么（Keep）

1. **先定产品方向再写代码**。没有一上来就开干，而是先用一轮 AI 对话把"做什么、给谁用、解决什么"想清楚，避免写到一半推翻。
2. **mock 模式做成真规则引擎，不是假模板**。如果我偷懒写死"这是一段示例分析"，评委一眼看穿；现在 mock 是真的在切句、抽词、打分，换一段输入结果就变。
3. **配置全部走环境变量**。`config.py` 里没有一个真实 Key，`.env.example` 里是空的，部署时不会泄密。
4. **本机真截图**。没有用设计稿糊弄，是 Edge headless 打开本地服务截的真实页面。

## 三、做错了什么（Problem）

### 问题 1：第一次启动就踩了"多 Python 环境"的坑

- **现象**：`pip3 install flask` 显示成功，但 `python app.py` 报 `No module named flask`。
- **根因**：`pip3` 指向的 Python 和 `python` 指向的不是同一个。
- **教训**：Windows 上永远用 `python -m pip install ...`，保证装到当前解释器里。
- **改进**：以后写 README 时把"用 `python -m pip`"作为强制写法，不留给别人踩坑。

### 问题 2：mock 关键词抽取一开始会把"的了和"抽出来

- **现象**：第一次跑 mock，关键词里出现一堆无意义单字。
- **根因**：正则只限制了长度，没限制词性。
- **改进**：加了停用词表 + 包含关系去重。但这仍然是"伪分词"——真正的中文分词该上 jieba。
- **后续 v2 计划**：`pip install jieba`，用 `jieba.analyse.extract_tags` 替换正则抽取，关键词质量会再上一个台阶。

### 问题 3：结果页一开始有重复内容

- **现象**：右栏"改写方向建议"和底部"改进建议"是同一组话，显示两遍。
- **根因**：`ai_service.mock_analyze` 把建议同时塞进了 `sections[2]` 和顶层 `suggestions` 字段，前端两个都渲染了。
- **改进**：删掉前端那个冗余 block。这是一个"接口字段没定清楚"的典型问题——mock 和 real 两种模式下字段语义不一致。
- **v2 改进**：统一成"sections 是唯一展示源"，`suggestions` 字段直接删掉。

### 问题 4：没真部署，这是 C6 的硬伤

- **现状**：只在 `127.0.0.1:5050` 跑通，没有公网 URL。
- **为什么没做**：部署需要本人的 Vercel / GitHub 账号，我作为执行者不能替用户注册账号、绑手机、过验证码。
- **我交付了什么**：`docs/部署说明.md` 写了从零到上线的分步指南，把"哪一步需要本人账号"标清楚。
- **用户下一步必须做**：按部署说明在自己账号上跑一次 `vercel deploy`，把真实 URL 填进 `阮依涵_C6_app链接.md`。

### 问题 5：没有写单元测试

- **现状**：靠手点页面验证，没写 `test_ai_service.py`。
- **为什么没做**：时间紧，优先保证"能跑、能截图、文档齐"。
- **v2 改进**：至少给 `_score_text`、`_extract_keywords`、`analyze` 的错误分支写 3-5 个 pytest 用例。

## 四、如果再做一次（Change）

1. **先写接口契约再写代码**：把 `POST /api/analyze` 的请求/响应 JSON 用一个示例文件定下来，前端后端对着同一份字段表写，避免问题 3。
2. **部署前置**：第二天就推 GitHub + Vercel，不要等到最后。本地跑通当天就部署，部署出问题早暴露。
3. **真实 Key 跑一次再交**：哪怕花几块钱 API 费用，也要让"真实 AI 模式"有一张真实截图，而不是只跑 mock。
4. **用 jieba**：中文分词别再用正则，关键词质量是用户第一印象。
5. **录 demo 视频**：30-60 秒，按 `docs/Demo录制说明.md` 走。
