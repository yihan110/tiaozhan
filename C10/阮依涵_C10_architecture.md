# 阮依涵_C10_architecture.md — 第二大脑五层架构

> 本文件同时作为顶层 `阮依涵_C10_architecture.md` 的内容（见根目录副本）。

## 0. 设计目标
为阮依涵（软件工程大一 / 无人机社团副社长 / 备赛四级与竞赛）搭建一个 **Markdown 驱动、零代码、可持续 10 年** 的个人 Agent 系统。
核心约束：
- 不依赖特定 App（Obsidian/Notion 都能打开，纯 .md 也能跑）；
- 每次使用都产生 ΔR，而不是一次性文档；
- 所有 Skill 必须来自她真实场景（通知、简历、高数、调试、调研、周计划、复盘）。

## 1. 五层总览
```
┌──────────────────────────────────────────────┐
│ L5 Interface   Markdown 文件夹 + AI 对话窗口   │
├──────────────────────────────────────────────┤
│ L4 Tool        豆包/DeepSeek、VSCode、微信、  │
│                GitHub、华为云、WPS、Notion     │
├──────────────────────────────────────────────┤
│ L3 Agent Loop  KSTAR：K→S→T→Â→A→R→ΔR→Memory │
├──────────────────────────────────────────────┤
│ L2 Skill       6 个已上线 Skill（见 skills/） │
├──────────────────────────────────────────────┤
│ L1 Memory      L1_raw / L2_episodes /        │
│                L3_skills / L4_identity        │
└──────────────────────────────────────────────┘
```

## 2. Layer 1 — Memory（四层记忆）

### L1 原始输入（memory/L1_raw/）
- **存什么**：课堂笔记、AI 对话片段、活动现场速记、情绪日记、OCR 出来的题目照片文字。
- **怎么写入**：手机备忘录 / 微信文件传输助手 / 直接新建 `YYYY-MM-DD_主题.md`。
- **怎么读取**：按日期排序，每周日晚由 `aar-generator` 批量扫一遍。
- **示例文件**：
  - `2026-09-15_华为ICT备赛笔记.md`（L1，未结构化）
  - `2026-10-08_四级出分情绪.md`（情绪记录）
  - `2026-10-20_三下乡三坟村对接.md`（村支书电话前的准备）

### L2 KSTAR 经验（memory/L2_episodes/）
- **存什么**：把 L1 笔记按 S→T→A→R 结构整理后的经验，每条带 ΔR。
- **怎么写入**：每周日晚用 `aar-generator` 把本周 L1 中"反复出现 2 次以上"的事件升级成 L2。
- **怎么读取**：遇到类似场景先 `grep` 主题关键词，把命中的 L2 喂给 AI。
- **示例文件**：
  - `2026-09-20_华为ICT省赛复盘.md`
  - `2026-10-10_四级失利复盘.md`
  - `2026-10-25_寝室卫生通知润色.md`
  - `2026-10-28_高数二重积分可视化教学.md`

### L3 Skill（memory/L3_skills/ → 指向 skills/）
- **存什么**：从 ≥3 条同类 L2 经验抽象出的可复用行动计划。
- **怎么写入**：当同一类事件在 L2 中出现 3 次以上，就新建一个 Skill 文件夹。
- **怎么读取**：见 `AGENT.md` 的"调用规则"表。
- **已上线 6 个**：notice-hardener / resume-expander / math-visual-tutor / debug-workflow / research-scanner / weekly-planning / aar-generator。

### L4 Identity（memory/L4_identity/）
- **存什么**：我是谁、我能调什么工具、我的原则、长期目标。
- **文件**：`identity.md`（身份与原则）、`tools.md`（工具清单与调用方式）。
- **怎么读取**：每次 KSTAR 循环的 K 阶段必读。

## 3. Layer 2 — Skill System
- 每个 Skill 一个文件夹，含 `SKILL.md`（指令）+ `usage.md`（使用次数与迭代记录）。
- 生命周期：候选 → 手动验证 1 次 → 上线 → 每次用后写 usage.md → ΔR 连续 3 次 > 阈值则重构。
- 详见 `skills/` 目录与顶层 `阮依涵_C10_skill汇总表.md`。

## 4. Layer 3 — Agent Loop（KSTAR）
- 主循环定义见 `AGENT.md`。
- **ΔR 量化约定**：
  - 写作类：字数偏差、AI 味句子数量、是否被社长/老师直接通过。
  - 学习类：题目正确率、能否给别人讲明白。
  - 备赛类：模拟分数、用时。
  - 情绪类：睡眠时长、是否还在凌晨 2 点醒。
- 每次循环后必须在 `logs/` 落一行记录，否则不算"用过"。

## 5. Layer 4 — Tool / Access
| 类别 | 工具 | 用途 |
|------|------|------|
| LLM | 豆包 / DeepSeek / Kimi | 写作、润色、辅导、复盘 |
| 代码 | VSCode + Python | 作业、调试、脚本 |
| 笔记 | 本文件夹（Markdown） | 记忆系统载体 |
| 通讯 | 微信文件传输助手 | L1 快速捕获 |
| 办公 | WPS / 飞书文档 | 社团通知、简历投递 |
| 云端 | GitHub（私有仓） | 每月备份一次整个第二大脑文件夹 |

## 6. Layer 5 — Interface
- 主用：**Markdown 文件夹 + AI 对话窗口**。
- 辅助：手机端用微信"文件传输助手"快速记 L1，周末回电脑端整理。
- 不做 Web UI / CLI——大一学生时间紧，Markdown 是最低维护成本。

## 7. 设计决策记录（为什么这么做）
| 决策 | 选择 | 理由 |
|------|------|------|
| 存储格式 | 纯 Markdown | 不被 Obsidian/Notion 锁定，10 年后还能打开 |
| 记忆层数 | 4 层（L1-L4） | 严格对应 CHALLENGE.md 的 KSTAR，不自己发明 |
| Skill 数量 | 6 个 | 覆盖她真实高频场景，不凑数 |
| 是否写代码 | 不写 | 她还在学 Python，先把"习惯"跑通，代码是后期优化 |
| 备份 | 每月 push 一次 GitHub 私有仓 | 防手机丢失 / 电脑重装 |
