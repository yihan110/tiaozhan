# 阮依涵_C10_拿来说明.md — 参考系统清单

> 本系统不是从零设计的。下面 4 个参考系统，每个都说明：它是什么、我拿了什么、我改了什么。

## 参考 1：Claude Code / 豆包的 Skill（AGENTS.md / SKILL.md）体系
- **它是什么**：把"做某类事的固定步骤"写成一个 Markdown 文件，AI 每次遇到类似场景就读它。
- **我拿了什么**：
  - `SKILL.md` 的 YAML frontmatter（name + description）
  - 文件夹即 Skill 的组织方式（一个 Skill 一个文件夹）
  - "触发条件"概念（When to Use）
- **我改了什么（adopted / removed / improved）**：
  - ✅ Adopted：SKILL.md 模板
  - ❌ Removed：它们的"三层加载"机制（全局→项目→本地）对我太重，大一学生不需要
  - 🔧 Improved：加了 `usage.md` 子文件，强制每次用后写 ΔR——这是原系统没有的进化闭环

## 参考 2：Obsidian / Notion 的"第二大脑"方案
- **它是什么**：用双链笔记把所有笔记连起来，形成个人知识库。
- **我拿了什么**：
  - 文件夹分层组织思想
  - "MOC（Map of Content）"概念 → 我把它变成 `memory/L3_skills/README.md` 索引
- **我改了什么**：
  - ✅ Adopted：Markdown 作为载体
  - ❌ Removed：双链、标签、图谱——这些功能好看但我根本不用，反而增加维护成本
  - 🔧 Improved：用 KSTAR 四层（L1/L2/L3/L4）替代自由标签。Obsidian 笔记存了找不到，KSTAR 强制结构化，能 grep。

## 参考 3：PARA 方法（Tiago Forte）
- **它是什么**：Projects / Areas / Resources / Archive 四层分类法。
- **我拿了什么**：
  - "进行中 vs 归档"的思想 → 我用 inbox/ 和 memory/L1_raw/ 的分离体现
- **我改了什么**：
  - ✅ Adopted：inbox 概念
  - ❌ Removed：PARA 的四层分类——它是笔记方法，不是 Agent 系统，没有"经验→技能"的转化
  - 🔧 Improved：用 KSTAR L1→L2→L3 的转化链替代 PARA 的静态分类。PARA 是"存起来"，KSTAR 是"存起来还要用"。

## 参考 4：LangChain / AutoGPT 的 Agent Loop
- **它是什么**：LLM 自动规划→调用工具→观察结果→再规划。
- **我拿了什么**：
  - "循环"概念：每次任务都走一遍 K→S→T→Â→A→R
  - "工具调用"概念：每个 Skill 声明需要什么 Tools
- **我改了什么**：
  - ✅ Adopted：循环结构
  - ❌ Removed：自动规划、自动工具选择——大一学生让 AI 全自动太危险（会编数据）
  - 🔧 Improved：改成**人驱动的半手动循环**。AI 出步骤，我决定用不用；ΔR 由我手写。这是对 LangChain 的反向简化。
